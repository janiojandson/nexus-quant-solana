# Unified 4D SHADOW execution and verification

This document describes the isolated Quant/Sentinel integration as verified on 2026-10-10. It is an execution record for controller review, not evidence that migrations, service configuration or deployment have occurred.

## Runtime flow

Sentinel runs as OBSERVER. Its PumpPortal/owned Helius subscriptions observe candidates and persist CANDIDATE handoffs; bonding-curve progress does not prove a tradable pool. Quant claims a fenced lease, verifies a supported physical pool, refreshes metadata for the exact mint and invokes the same admission component used by Jupiter discovery. Acknowledgement follows a durable entry receipt and current lease ownership. A lost post-commit acknowledgement is recovered by the original Sentinel source event, not by buying again.

Quant discovery uses Jupiter Tokens V2. Missing prices, metadata, first-pool identity or market facts stay unknown; observations and creation timestamps are distinct. Supported pool proofs are legacy SPL PumpSwap and Raydium CPMM with canonical program/PDA, account layout, vault mint/owner/state and coherent fresh slots. PumpSwap global buy/sell flags must allow trading. Reserve means physical WSOL vault balance after accrued protocol/fund fees; virtual credit is excluded. Token-2022, CLMM and legacy Raydium V4 are unsupported and fail closed.

Admission requires measured critical security facts and four dimensions: mint/freeze authority checks; physical reserve at least MIN_POOL_RESERVE_SOL (default 20, finite and positive); exact allocated forward/reverse quote loss below 5%; and a fresh unsigned final Jupiter transaction simulated through CRITICAL RPC with value.err=null and a supported bound inner CPI. Quotes use a requested 100 bps limit and retain the 750 bps hard cap. Unknown/missing route, fee, minimum output, simulation trace, stale proof, budget or lease denies entry. No failed/void preflight becomes acceptance. The common runtime entry admission currently registers SHADOW only; changing flags to LIVE does not enable an unchecked entry fallback.

Momentum requests start nominally at 0/500/1000/1500 ms. Start lateness is bounded separately (100 ms); each quote has a default 400 ms completion budget. The last response may finish at 1.9 s. Those are configured deadlines, not measured provider p95 or an exact 1.5 s completion promise.

SHADOW entry and exits persist into mode-separated ledger/fill tables. Fill IDs are immutable/idempotent; initial capital remains fixed, remaining cost follows the actual remaining atomic amount, and cumulative proceeds are additive. TP1 at +35% sells ceil(tokens/(1+PnL)), rather than a fixed 74.07% or 50%. A fresh exact partial quote must conservatively recover nominal principal or the decision becomes HOLD/requote. TP2 at +100% sells ceil(remaining tokens/2). Only the post-TP2 moonbag trails 10% below its persisted executable high-water mark. Full protective exits precede partial profit exits. There is no TP3 forced liquidation. Physical reserve below the configured floor triggers a full SHADOW protective exit; RPC absence is unknown and cannot fabricate a drain.

Quote HOLD is a normal retry, distinct from ambiguous persistence/apply failure that locks reconciliation. Restart reads only the active accounting mode and restores amount, cost, TP step and watermarks. SHADOW never reconciles real wallet token balances into hypothetical positions. Paper proceeds, conservative cost estimates and rent=0 remain hypothetical; they are not wallet-confirmed profits or principal recovery. Existing LIVE exit support requires an immutable ledger and actual confirmed wallet delta/fee evidence before local accounting effects; it was tested only with offline fixtures, and has no deployment authority here.

Time protections retained by the implementation include the base 10-minute stop, 25-minute extension for positive PnL, 20-minute neutral extension with growing volume, and the 5-minute stagnant negative-PnL branch. These have not been recalibrated in Task6.

## Explicit unresolved economic semantics

The user confirmed a -12.5% gross price stop BEFORE fees/network. Current SHADOW monitoring feeds a conservative net liquidable quote (minimum output minus configured bps haircut, network fee and rent reserve) to the -12.5% engine. These metrics are different: fees can trigger the implemented stop sooner than a gross price decline of 12.5%. Task6 deliberately preserves approved numeric thresholds and reports this gap for review; it does not claim the newly clarified gross-stop requirement has been implemented.

The round-trip loss gate remains <5%; the user has not chosen its recalibration. The additional feeBps haircut is a conservative assumption and may double-count an amount already included in quote output. Exact feeMint/totalInput/totalOutput reconciliation and provider evidence would be needed to label it an actual net fee calculation. No profitable edge, zero-delay execution, actual recovery or provider compatibility is established by these fixtures.

## Safe configuration and controller execution gates

Set SHADOW_MODE=true and DRY_RUN_MODE=true for both services; Sentinel role is OBSERVER. Keep one replica per service for the local budget coordinator. Use the six-entry HELIUS_CREDENTIALS manifest with only references to secret variables: Quant owns keys 1–3 (CRITICAL plus STATE), Sentinel keys 4–6 (STATE only). Use the shared nonsecret HELIUS_QUOTA_GROUPS allocation UNKNOWN_SHARED, Quant 6 RPS / Sentinel 3 RPS, with 1 RPS headroom. Actual project independence, credits and other clients are unverified. Sentinel WebSocket limits/credits are independent of HTTP budgets. Quant subscriptions and research quote paths are disabled; keep PUMP_OBSERVATORY_ENABLED=false and PUMP_STRATEGY_LAB_ENABLED=false during this integration.

Quant requires four distinct configured Jupiter org IDs/key references: org1 PROTECTION, org2/3 ENTRY, org4 DISCOVERY. Four local 60-RPM role buckets are not proof of four independent provider allocations. See HUB_CONFIGURATION.md for mappings and host/transport policy. Do not use legacy direct RPC/axios diagnostics as financial runtime fallbacks.

Before upload, the controller must review/apply only approved additive schema changes to the existing shared DB, in a transaction with bounded lock/statement timeouts, and verify the resulting schema. The user waived backup on 2026-10-10; there is no backup/recovery guarantee. No ALTER COLUMN TYPE, DROP, DELETE or historical overwrite/backfill is authorized. Local SQL-boundary tests do not certify actual PostgreSQL concurrency or production migration behavior.

Deployment packaging requires a controller decision: Sentinel railway.json specifies DOCKERFILE and us-east4, while the controller's read-only service snapshot reports RAILPACK, one replica, us-west2. Uploading that file risks changing the configured build/region. Sentinel Dockerfile runs entrypoint.sh, whose optional START_LAYA_CMD branch is inactive according to the controller's current variable snapshot; do not activate it. Its dependency installation uses npm install, not a lock-enforced npm ci. Quant also has a Dockerfile and no local .railwayignore/.dockerignore. Do not assume git-excluded .superpowers or ignored .env files are excluded from every packaging path. The controller should construct and inspect a clean upload bundle that excludes secrets, .git, node_modules, dist/coverage/logs and review artifacts and preserves the approved current build/region. Task6 did not change infrastructure or packaging configuration.

After whole-branch spec/quality review, the controller alone may configure variables, run the approved additive transaction, upload SHADOW services and verify concrete deployment IDs, health and mode. Remaining gross/net stop semantics must be visible in the handoff, and deployment must not be described as an approved financial recalibration. No LIVE signing, broadcast, key import, Docker startup or purchase is authorized.
